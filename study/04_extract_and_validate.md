# 4장. 추출과 검증 — 후보를 만들고, 맞는 것만 통과시킨다

**이 장의 목표**: 정형 · 문서별 추출 방법을 고르고, 자동 검사와 사람 검토를 어떻게 나눌지 설계할 수 있다. LLM 결과를 어디까지 믿을지 안다.
관련 질문: Q012 · Q013 · Q015 · Q017 · Q023 · Q027 · Q034

---

## 4.1 추출 — 정형은 규칙, 문서는 스키마 고정 LLM
| 방법 | 장점 | 단점 | 맞는 경우 |
|---|---|---|---|
| 규칙 · 템플릿 매핑 | 정확 · 싸고 재현됨 | 자유 서술 못 함 | DB · export · 양식 문서 |
| 전통 NLP (개체명 인식 + 관계 분류) | 빠르고 저렴 | 라벨 · 도메인마다 재학습 | 같은 유형 문서가 아주 많을 때 |
| LLM · 스키마 고정 | 라벨 없이 시작 · 문맥 이해 | 비용 · 흔들림 · 그럴듯한 오류 | 메일 · 회의록 |
| LLM · 자유 추출 | 모르는 개념 발굴 | 이름이 쪼개짐 | 온톨로지 확장 후보 찾기 |

- **우리 선택(19a장)**: CMMS · MES는 매핑 규칙, 메일 · 회의록은 스키마 고정 LLM. 결과는 전부 "후보".
- 프롬프트에 넣는 것: 관계 목록(정의 파일에서 자동 생성), 알려진 개체, 예시 · 반례, "추정 표현은 suspected로", "근거 구절은 원문 그대로 복사".
- 흔한 LLM 오류: 추정 → 확정, 예정 → 완료, 부정문 → 원인, 관계 방향 뒤집기. 데모에서도 "금요일 교체 예정"을 확정으로 뽑았고 검증의 '예정' 검사가 잡았다(18장).

## 4.2 정의 파일에서 검사 장치를 만든다
- 정의 YAML 하나에서 **LLM 출력 JSON 스키마 · 적재 전 검증 코드 · DB 제약 · (선택) SHACL**을 생성한다(17 · 17a장). 정의가 한 곳에 있으니 서로 어긋나지 않는다.
- YAML 밖에서 온 것: 버리지 않고(원본 · 청크로 검색은 됨) 확장 후보 큐로 → 자주 나오면 정의를 고치는 PR → 버전 올림 → 해당 원본만 재추출. 정의를 자동으로 늘리지 않는다(조회 · 검증 · 지표가 같이 바뀌므로).

### 구조화 출력(Q027) — 형식을 어길 수 없게
- LLM이 글자를 만들 때 JSON 스키마에 맞지 않는 글자는 고를 수 없게 막는 기능(제약 디코딩). vLLM이 지원한다(`response_format`의 json_schema 또는 vLLM 전용 옵션 — 버전 문서 확인).
- 오픈웨이트 모델일수록 효과가 크다. 관계 이름을 `enum`으로 주면 목록 밖 이름이 아예 안 나온다.
- **형식만 보장한다.** 내용은 검증의 일.

### 이전 호출 재생(Q023)
- 데모는 LLM을 실제로 부른 요청 · 응답을 파일에 저장해 두고(`runs/recorded/`), 다음엔 다시 부르지 않고 그 응답을 쓴다(record/replay). 발표 중 결과가 바뀌지 않게, LLM 서버 없이도 돌게.
- 프롬프트가 바뀌면 해시가 달라져 "다시 호출해 저장하라"고 알려 준다.

## 4.3 검증 — 싸고 확실한 것부터
1. **규칙 · 스키마**: 허용 타입 · 관계 방향 · 필수값 · 허용 값 · 참조 무결성(없는 설비). 전수, 싸다.
2. **원문 대조**: LLM이 적은 근거 구절이 원문에 그대로 있나. 원문이 그 사실을 뒷받침하나(함의).
3. **원천 대조**: 속성마다 기준 시스템(완료 시각 = CMMS). 다르면 덮어쓰지 않고 보류.
4. **사람**: 위험 × 확신 기준에 걸린 예외만.

### SHACL · n10s · Aura(Q013)
- **SHACL**: W3C 표준 그래프 검증 규칙("작업은 설비가 정확히 1개"). RDF 계열에서 주로 쓴다.
- **n10s**: Neo4j와 RDF를 잇는 Neo4j Labs 플러그인(RDF/OWL 가져오기 · SHACL 검증).
- **Aura**: Neo4j 클라우드 서비스. 플러그인을 마음대로 못 올린다.
- 우리(사내 · Community)는 같은 검사를 **적재 전 Python 코드**로 한다. DB와 무관하게 동작.

## 4.4 언제 사람에게 묻나 (22장)
- 두 축: **위험도**(안전 · 품질 영향, 공식 기록과 다름, 되돌리기 어려운 병합) × **확신도**(추정 표현, 근거 하나뿐, 출처 충돌, 애매한 ER 점수).
- 확신 높고 위험 낮은 칸 = **자동 반영 + 사후 표본 검수**. 전부 보는 게 아니라 무작위 몇 건으로 오류율을 재고 자동 범위를 조정(acceptance sampling).
- 사내 데이터별 경로:

| 데이터 | 가는 곳 | 사람이 하는 일 |
|---|---|---|
| CMMS · MES 원천 기록 | 자동 반영 | 주 1회 무작위 확인 |
| 엑셀 · CSV 형식 오류 | 데이터 담당자 | 행이 아니라 원천 · 규칙을 고침 |
| 문서 ↔ 공식 기록 불일치 | 담당자 확인 | 예/아니오 |
| 고장 원인 · 안전 판단(추정) | 전문가 검토 | 주간 회의에서 묶어서 |
| 지시어 · 정보 부족 | 질문 큐 | 새 문서로 자동 해소 시도 → 작성자에게 질문 |

## 4.5 질문 큐의 자동 해소 (27장, Q017)
- 새 문서가 들어오면 열린 질문과 대조. **먼저 프로그램으로 거른다**(같은 설비 · 같은 기간인가) → 겹치는 것만 LLM에 "이 문서가 답하나?".
- 위험이 낮고 근거가 명확하면 자동으로 닫고, 애매하면 "답 후보 + 근거 문장"을 붙여 담당자에게 예/아니오만 묻는다. 자동으로 닫은 것도 근거와 표본 확인을 남긴다.

## 4.6 LLM 판정을 믿어도 되는 만큼만 (Q034)
- LLM-as-a-judge에는 위치 · 길이 · 자기 모델 선호 같은 편향이 보고됐다. LLM 판정만으로 KG 정확도를 재면 실제와 크게 차이 날 수 있다(21장).
- 쓰는 법: 사람이 판정한 표본 100~200건으로 일치율과 "통과시켰는데 틀린 것" 비율을 먼저 재고, 1차 거름망으로만 쓴다. 가능하면 추출 모델과 다른 모델로 판정. 모델 · 프롬프트를 바꾸면 다시 잰다.

1. 구조화 출력이 보장하는 것과 보장하지 않는 것은?
2. 메일의 "3/6 교체 완료"와 CMMS의 "3/7 10:20"이 다를 때 처리는?
3. 확신 높고 위험 낮은 후보를 사람이 전부 보지 않아도 되는 근거는?
