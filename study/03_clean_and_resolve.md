# 3장. 정제와 개체 연결 — 같은 것은 같게, 다른 것은 다르게

**이 장의 목표**: 규칙 · 사전 · 확률 모델 · LLM을 어디에 쓰는지 구분하고, 사람이 "건"이 아니라 "기준"을 관리하는 구조를 설계할 수 있다.
관련 질문: Q006 · Q007 · Q011 · Q029 · Q033

---

## 3.1 정규화는 층을 나눈다
규칙만으로는 확장되지 않는다(표현은 끝없이 다양하다). 일반적인 층:
1. **규칙**: 날짜 · 단위 · 코드 패턴처럼 형식이 정해진 것 (`3/6 오후` → 문서 작성일 기준 날짜)
2. **용어 사전 조회**: 표준어 · 동의어 · 숨은 표기(SKOS의 prefLabel · altLabel · hiddenLabel 구조)
3. **후보 생성**: 문자열 유사도 + 임베딩으로 사전 항목 상위 몇 개
4. **선택**: 분류기나 LLM이 후보 중 하나 또는 "해당 없음(NIL)"
5. **NIL 처리**: 원래 표현을 보존하고 "미연결" 표시 → 큐 → 빈도순으로 사람이 사전에 추가 → 영향받는 문서 재처리

- LLM에 맡길 때는 사전 후보를 함께 주고 출력을 "기존 ID 또는 NEW"로 제한한다. 없는 ID는 검증에서 막는다.
- 운영 지표: 연결률, NIL 비율 추이, 검토 대기량.

## 3.2 사람은 건이 아니라 기준을 고친다
- 문서마다 사람이 보는 구조는 불가능하고 필요도 없다. 사람은 **규칙과 사전**을 관리한다(데이터 품질 · MDM의 data steward 역할).
- 표현은 롱테일(Zipf) 분포라 상위 소수 용어가 언급 대부분을 덮는다. "압력센서 V42"가 200번 나왔으면 사전에 한 줄 추가 → 200건 + 앞으로 들어올 문서까지 해결.
- 사람이 꼭 개입할 곳은 좁다: 새 용어를 사전에 넣을지, 두 코드가 정말 같은 대상인지(되돌리기 어려운 병합).
- 큐가 계속 커지면 사람을 늘리기보다 규칙 · 모델을 고친다.

## 3.3 Entity Resolution(ER) — 같은 대상을 같은 ID로
- 두 종류: 레코드 ↔ 레코드(CMMS 설비 표 ↔ MES 설비 표), 언급 ↔ 개체("17호기" → EQ-017, entity linking).
- 절차: 표준화 → **블로킹**(비교 범위 줄이기: 같은 FAB끼리) → 필드별 비교 → 판정 → 클러스터링 → 대표 레코드 → 평가.
- **Fellegi-Sunter**: 필드가 일치할 확률을 "같은 대상일 때(m)"와 "남인데 우연히(u)"로 나눠 점수를 낸다. EQ-017은 FAB마다 재사용되니 u가 높아 **약한 증거**, FAB + 코드 + 일련번호가 다 맞으면 u가 매우 낮아 **강한 증거**(16장). 임계값 두 개로 같음 / 검토 / 다름.
- 현업 순서: ① 기준 마스터가 있으면 "서로 중복 찾기"가 아니라 "마스터에 연결"(훨씬 쉬움) ② 업무 키 정확 일치로 대부분 ③ 나머지는 확률 모델(Splink, 라벨 없이 EM 학습) ④ 텍스트 언급은 사전 + 문서 맥락(FAB · 팀)으로 후보 ⑤ 중간 점수대는 검토 큐 ⑥ 내부 ID를 영구 유지하고 병합 기록을 남김(물리 병합 대신 SAME_AS로 되돌릴 수 있게).
- 잘못 합치면 이력이 섞이고 되돌리기 어렵다. 못 합치면 검색에서 빠지지만 나중에 합치기 쉽다 → **애매하면 합치지 않는다.**

## 3.4 방법 비교와 우리 선택 (16a장)
| 방법 | 장점 | 단점 | 맞는 경우 |
|---|---|---|---|
| 규칙 · 사전 | 설명 가능 · 빠름 | 새 표현 못 잡음 | 정해진 형식 · 자주 나오는 용어 |
| 확률적 ER (Splink) | 라벨 없이 대량 레코드 | 비교 필드 설계 | 여러 시스템의 정형 레코드 |
| 학습 기반 (Dedupe · Ditto) | 정확 | 라벨 필요 | 라벨을 모을 수 있을 때 |
| LLM 판정 | 문맥이 필요한 애매한 언급 | 비용 · 흔들림 · 없는 ID | 남은 소수의 텍스트 언급 |

**우리 선택**: 규칙 + 사전 우선 → 정형 레코드는 키 일치 후 필요하면 Splink → 남는 애매한 언급만 LLM 후보 + 사람 검토.

## 3.5 더 알면 좋은 것
- **임베딩 + 재정렬로 후보 찾기(Q029)**: ① 임베딩으로 사전 전체에서 비슷한 후보 10개를 빠르게(bi-encoder) ② 재정렬 모델이 한 쌍씩 꼼꼼히 비교(cross-encoder). 글자가 다른 같은 대상("PT-V42" ↔ "압력센서 V42")을 잡는다. 사전에 안 걸린 표현에만 쓰고, 코드는 자동 확정하지 않는다.
- **능동 학습 · 약한 지도(Q033)**: 헷갈리는 것부터 사람에게 묻고(능동 학습), 반복되는 판정은 규칙(라벨링 함수)으로 만들어 다음부터 자동 처리(Snorkel). 검토 큐가 밀리지 않게 하는 장치. 무작위 표본 검수는 따로 유지.
