# 개발 노트 — 무엇을 가져다 쓰고, 무엇을 만들었나

단계별 상세(무엇을 직접 짰고 · 정의했고 · LLM에 맡겼고 · 가져다 썼는지, 어려웠던 점)는 [dev_work.yaml](dev_work.yaml)에 있고, 웹의 "구현 내용" 토글이 실제 코드와 함께 보여 줍니다. 이 문서는 전체 요약, 결정 기록, 실서비스로 갈 때 바뀔 것을 정리합니다.

## 1. 플랫폼 vs 직접 구현 (한눈에)
| 영역 | 가져다 쓴 것 | 직접 만든 것 |
|---|---|---|
| 저장 · 조회 | Neo4j 5 Community, Cypher, Python 드라이버, 유니크 제약 | 그래프 모델(어휘 그래프 · ReviewItem · OntologyCandidate), 변경 계획 → 반영, 멱등 확인 |
| 그래프 시각화 | **Neo4j Browser** | iframe 차단 헤더를 지우는 중계 포트, URL로 질의 채우기 |
| LLM | OpenAI 호환 API (JSON 모드) | 온톨로지 → 프롬프트 생성, 규칙 12개 프롬프트, 호출 저장 / 재생 |
| 정제 · 정규화 | 정규식, difflib | 메일 · STT 정제 규칙, 발음 복원 표, 상대 날짜, 사전 스캔 |
| 개체 연결 | — | 별칭 · 맥락 · 회사명→제품 · 유사도 판정기, 임계값 2개, 새 개체 등록 |
| 검증 | — | 스키마 · 근거 문장 · 기사 대조(역방향 포함) · 확신도 판정 |
| 웹 | Python `http.server` | 단계 화면 7개, 비교 화면, 구현 내용 패널 |

**정리하면** 플랫폼이 해 주는 것은 "저장, 질의, 그림, LLM 호출"까지입니다. 온톨로지 구축의 **판단 부분**은 전부 직접 만들어야 했습니다. 무엇을 지울지, 무엇이 같은 대상인지, 무엇을 믿을지, 무엇을 사람에게 물을지가 그 판단입니다.

## 2. 결정 기록
| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 의존성 `neo4j` + `PyYAML`만 | 망분리 · 오프라인 설치를 쉽게 | FastAPI, rapidfuzz (편하지만 설치가 늘어남) |
| 그래프 그림은 Neo4j Browser | 요구사항: Neo4j 제공 시각화 그대로 | NVL · neo4j-viz: 라이선스상 Aura·상용 제품 전용 |
| :8801 중계로 iframe 허용 | :7474는 `X-Frame-Options: DENY` | 새 탭으로만 열기 (대체 경로로 남김) |
| Community 1 DB에서 속성으로 전/후 구분 | 이식할 곳도 Community일 가능성 | DB 2개(main/develop) — Enterprise 필요 |
| 사실 근거는 관계 속성 + 어휘 그래프 | 단순하고 Browser에서 따라가기 쉬움 | Assertion 노드(사실 노드) — 근거가 많아지면 전환 |
| LLM 출력은 전부 후보, 검증 후 적재 | LLM이 방향을 틀리고 추정을 빠뜨림 (실측) | LLM 결과 바로 적재 |
| 호출 저장 / 재생 기본 | 발표 중 결과가 바뀌면 설명이 깨짐 | 매번 실시간 호출 |
| 온톨로지 변경은 제안 파일로만 | 온톨로지는 사람이 승인해야 함 | 자동 반영 |

## 3. 실제로 어려웠던 것 (개발하면서 겪은 순서)
1. **LLM 추출 품질**
   - 프롬프트 v1은 관계 방향을 자주 뒤집었습니다. 예: `HBM3E DEVELOPS 하이닉스`.
   - 추정 문장("얘기가 돈다")을 아예 빼 버리기도 했습니다.
   - v2·v3에서 방향 예시와 "추정도 suspected로 넣어라" 규칙을 추가했습니다.
   - 작은 모델(gpt-4.1-mini)은 그래도 불안정해서 gpt-4.1로 바꿨습니다. 그래도 `USES_COMPONENT` 방향은 여전히 틀립니다. 검증 단계가 "근거 기사 없음 · 반대 방향 사실은 있음"으로 잡아내고, 이 장면은 데모에 그대로 남겼습니다.
2. **온톨로지 밖 관계 이름이 실행마다 다름**: `PARTNERS_WITH`로 나오기도 하고 `JOINT_DEVELOPMENT`로 나오기도 합니다. 그래서 제안 화면에 "기사 코퍼스는 PARTNERS_WITH로 표기 — 이름 통일 필요"를 함께 보여 줍니다.
3. **STT 발음 복원**: "엘", "포"는 일반 음절이라, 앞 단어가 CoWoS나 HBM일 때만 바꾸는 규칙이 필요했습니다.
4. **동음 별칭**: "삼성"(Electronics/SDI)과 "SK"(hynix/Inc.)는 주변 문장의 맥락 단어로 가릅니다. 근거가 한 단어뿐이면 0.70으로 "검토"가 됩니다. 일부러 보수적으로 잡았습니다.
5. **비슷한 코드**: H20과 H200은 유사도가 0.86입니다. 코드는 유사도만으로 절대 확정하지 않게 했습니다.
6. **복합 표현**: "NVIDIA 블랙웰", "하이닉스랑 TSMC", "마이크론 것"처럼 LLM이 표현을 그대로 넘깁니다. 안쪽 별칭 고르기, "와/랑" 분리, "회사 이름으로 제품 지칭" 규칙을 각각 따로 만들었습니다.
7. **제품 단위 단순화**: "블랙웰"은 원래 제품군(아키텍처) 이름인데, 사전에서 B200의 별칭으로 넣었습니다. 실제로는 제품군 노드를 따로 두는 것이 맞습니다. 온톨로지 설계에서 **입도(granularity)**를 정하는 문제입니다.
8. **Neo4j Community 제약**
   - DB가 1개라 전/후를 속성으로 구분합니다.
   - 존재·타입 제약은 Enterprise 전용이라 필수 속성 검사를 파이프라인이 맡습니다.
   - 집계 뒤 `ORDER BY`에서 집계 전 변수를 쓰면 오류가 나서, 별칭으로 정렬하게 고쳤습니다.
9. **Neo4j Browser 임베드**
   - iframe 차단 헤더 때문에 중계 포트를 두었습니다.
   - URL로 질의를 채울 수는 있지만 자동 실행은 되지 않습니다.
   - 처음 한 번은 iframe 안에서 로그인해야 합니다.
   - 색은 라벨 기준이라, Diff 라벨 색을 범례에서 직접 지정해야 합니다.

## 4. 실서비스로 갈 때 바뀔 것
| 지금 (데모) | 실서비스 |
|---|---|
| 단계 산출물을 JSON 파일로 | 원장 DB(RDB)에 수집 기록 · 후보 · 판정 이력 |
| md 입력 2개 | 소스별 커넥터 + 변환기, 증분 수집, 스케줄러(Airflow 등) |
| 호출 저장 / 재생 | 실시간 호출 + 비용 · 지연 관리, 모델 · 프롬프트 버전 고정 |
| 검토는 ReviewItem 노드로 표시만 | 검토 UI, 권한, 승인 기록, 질문 큐 알림 |
| 기사 코퍼스 대조 | 공식 원천 시스템 API 대조 |
| 사전 · 발음 표를 손으로 | 미연결 큐에서 빈도순으로 사람이 추가하는 루프 |
| ER 규칙 몇 개 | 확률 모델(Splink 등) + 라벨 쌓기 |
| 온톨로지 제안 파일 | PR 리뷰 → 버전 태그 → develop KG 재구축 → 지표 비교 후 승격 |
| 1 DB · 속성 구분 | main / develop 인스턴스 분리 |
