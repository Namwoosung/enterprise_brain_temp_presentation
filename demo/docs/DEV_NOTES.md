# 개발 노트 — 무엇을 가져다 쓰고, 무엇을 만들었나

단계별 상세는 [dev_notes.yaml](dev_notes.yaml)에 있고, 웹의 "구현 노트" 버튼이 같은 내용을 보여 줍니다. 이 문서는 전체 요약, 결정 기록, 실서비스로 갈 때 바뀔 것을 정리합니다.

## 1. 플랫폼 vs 직접 구현 (한눈에)
| 영역 | 가져다 쓴 것 | 직접 만든 것 |
|---|---|---|
| 저장 · 조회 | Neo4j 5 Community, Cypher, Python 드라이버, 유니크 제약 | 그래프 모델(어휘 그래프 · ReviewItem · OntologyCandidate), 변경 계획 → 반영, 멱등 확인 |
| 그래프 시각화 | **Neo4j Browser** | iframe 차단 헤더를 지우는 중계 포트, URL로 질의 채우기 |
| 추출 | OpenAI 호환 API (JSON 모드) | CMMS 열 → 관계 매핑 규칙, 온톨로지 → 프롬프트 생성, 규칙 13개 프롬프트, 녹화/재생 |
| 정제 · 정규화 | 정규식, difflib, csv | CMMS 중복 행 · 날짜 형식, 메일 · STT 정제 규칙, 발음 복원 표, 날짜 · 단위 규칙, 사전 스캔 |
| 개체 연결 | — | 별칭 · 맥락(FAB) · CMMS 작업 대조 · 유사도 판정기, 임계값 2개, 새 작업 등록 |
| 검증 | — | 스키마 · 근거 문장 · 추정/예정 표현 · 기준 시스템(CMMS · 알람 로그) 대조 · 행 단위 보류 |
| 웹 | Python `http.server` | 단계 화면 7개, 비교 화면, 구현 노트 |

**정리하면** 플랫폼이 해 주는 것은 "저장, 질의, 그림, LLM 호출"까지입니다. 온톨로지 구축의 **판단 부분**은 전부 직접 만들어야 했습니다. 무엇을 지울지, 무엇이 같은 대상인지, 무엇을 믿을지, 무엇을 사람에게 물을지가 그 판단입니다.

## 2. 결정 기록
| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 의존성 `neo4j` + `PyYAML`만 | 망분리 · 오프라인 설치를 쉽게 | FastAPI, rapidfuzz (편하지만 설치가 늘어남) |
| 그래프 그림은 Neo4j Browser | 요구사항: Neo4j 제공 시각화 그대로 | NVL · neo4j-viz: 라이선스상 Aura·상용 제품 전용 |
| :8801 중계로 iframe 허용 | :7474는 `X-Frame-Options: DENY` | 새 탭으로만 열기 (대체 경로로 남김) |
| Community 1 DB에서 속성으로 전/후 구분 | 이식할 곳도 Community일 가능성 | DB 2개(main/develop) — Enterprise 필요 |
| 사실 근거는 관계 속성 + 어휘 그래프 | 단순하고 Browser에서 따라가기 쉬움 | Assertion 노드(사실 노드) — 근거가 많아지면 전환 |
| LLM 출력은 전부 후보, 검증 후 적재 | LLM이 방향을 틀리고 추정을 빠뜨림 (실측) | LLM 결과 바로 적재 |
| 녹화/재생 기본 | 발표 중 결과가 바뀌면 설명이 깨짐 | 매번 실시간 호출 |
| 온톨로지 변경은 제안 파일로만 | 온톨로지는 사람이 승인해야 함 | 자동 반영 |

## 3. 실제로 어려웠던 것 (개발하면서 겪은 순서)
> 이 데모는 처음에 반도체 · AI 뉴스 도메인으로 만들었다가 사내 설비 정비 도메인으로 다시 만들었습니다. 아래는 두 버전을 만들며 겪은 것입니다.

1. **LLM 추출 품질**
   - 첫 프롬프트는 관계 방향을 자주 뒤집었고, 추정 문장을 아예 빼 버리기도 했습니다. 방향 예시와 "추정도 suspected로 넣어라" 규칙을 추가했습니다.
   - 작은 모델(gpt-4.1-mini)은 불안정해서 gpt-4.1을 씁니다.
   - 그래도 이 데모의 녹화본에서 LLM은 "B동 17호기 USED_PART_TYPE RF 제너레이터"처럼 정비 작업 대신 설비를 주어로 뽑습니다. 스키마 검사가 거절하고, 이 장면을 데모에 그대로 남겼습니다.
   - "금요일 교체 예정"을 confirmed로 표시합니다. 근거 문장에 "예정 · 추정"이 있으면 확정으로 보지 않는 검사를 따로 두었습니다.
2. **번호 없는 정비 작업**: 메일 · 회의는 "3/6 P/T V-42 교체"처럼 작업 번호 없이 말합니다. 문서에서 작업을 새로 만들지 않고, CMMS에서 같은 설비 · 부품 · 날짜의 작업을 찾아 연결합니다. 날짜가 하루 다르면(메일 3/6 · CMMS 완료 3/7 10:20) 자동으로 같다고 하지 않습니다.
3. **설비 코드 재사용**: EQ-017은 FAB-A와 FAB-B에 다 있습니다. 키를 `FAB + 코드`로 두고, 코드만 나오면 주변 문장의 FAB 단서로 가릅니다. 단서가 없으면 검토입니다.
4. **STT 발음 복원**: "피티 브이 사십이", "오백 밀리토르", "에이동 십칠 호기"를 코드 · 단위로 되돌리는 표가 필요했습니다. 뉴스 버전에서는 "엘", "포"처럼 일반 음절과 겹치는 발음 때문에 앞 단어 조건 규칙도 만들었습니다.
5. **비슷한 코드**: CMMS 행의 EQ-071은 EQ-017 · EQ-018과 비슷합니다. 같은 행의 일련번호 SN-A017이 EQ-017을 가리켜도 자동으로 고치지 않고 행 전체를 보류합니다.
6. **문서 vs 기준 시스템**: 메일과 CMMS가 다를 때 프로그램은 어느 쪽이 맞는지 모릅니다. 속성마다 기준 시스템을 정하고(완료 시각 = CMMS) 불일치를 사람에게 넘깁니다. 실제로는 CMMS 입력 지연이 원인일 수 있습니다.
7. **입도(granularity)**: 고장 "증상"(압력 흔들림)과 "PM 주기"는 v1 온톨로지에 없습니다. LLM이 온톨로지 밖 관계로 따로 모으고, v1.1 제안으로 넘깁니다.
8. **Neo4j Community 제약**
   - DB가 1개라 전/후를 속성으로 구분합니다.
   - 존재·타입 제약은 Enterprise 전용이라 필수 속성 검사를 파이프라인이 맡습니다.
   - 집계 뒤 `ORDER BY`에서 집계 전 변수를 쓰면 오류가 나서, 별칭으로 정렬하게 고쳤습니다.
9. **Neo4j Browser 임베드**
   - iframe 차단 헤더 때문에 중계 포트를 두었습니다.
   - URL로 질의를 채울 수는 있지만 자동 실행은 되지 않습니다.
   - 처음 한 번은 iframe 안에서 로그인해야 합니다.
   - 색은 라벨 기준이라, Diff 라벨 색을 범례에서 직접 지정해야 합니다.
