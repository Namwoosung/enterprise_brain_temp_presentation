## 6.1 NVIDIA Auto Ontology에서 가져올 것 (Q019)
- **무엇인가**: RDB 메타데이터(스키마 · 표본 · 쿼리 이력)에서 시맨틱 레이어(용어 · 매핑 · 관계 · 지표) 초안을 만들고(Generate) → 사람이 실제 질문으로 시험 · 수정해 인증하고(Certify) → agent가 그걸로 SQL을 만들어 답하는(Answer) 오픈소스(Apache-2.0, 2026-11 공개).
- **만드는 방식의 핵심**: 표본 · 형식 · 조인 확인은 규칙(결정적), 이름 · 설명 · 관계 제안은 LLM. **LLM이 제안한 관계는 실제 조인이 행을 돌려줄 때만 저장**(데이터로 검증).
- **주의**: 결과는 OWL 같은 형식 온톨로지가 아니라 text-to-SQL용 매핑. 비정형 문서는 다루지 않음. 공식 문서 스스로 "인증은 표시일 뿐 조회를 막지 않는다"고 적고 있음.
- **우리에게**: ① MES · CMMS 스키마 + 쿼리 이력으로 초안 만들기 ② LLM 제안은 데이터로 검증 ③ 계산식(지표)도 정의에 포함 ④ 인증이 실제로 막도록(게이트) 직접 설계 ⑤ 문서 쪽은 우리 파이프라인.

## 6.2 Airflow와 DAG (Q020)
- **Airflow** = 작업 흐름을 Python 코드로 정의하고 정해진 때 실행 · 재시도 · 기록하는 오케스트레이터. 데이터 처리 자체가 아니라 "언제 · 어떤 순서로 · 무엇을".
- **DAG** = 작업(task)과 순서의 묶음(순환 없음). 예: 수집 → 정제 → 추출 → 검증 → 적재.
- 꼭 알 것: task · operator, 스케줄(cron · 이벤트), 재시도, backfill(과거 구간 재실행), **멱등성**(다시 돌려도 같은 결과), XCom(작은 값 전달), Asset(데이터 기반 트리거).
- Airflow 3(2025-04): Dataset → **Asset**, 외부 이벤트로 깨우는 **Watcher**, **DAG 버전 관리**(실행이 시작 시점 코드 버전에 묶임, Git 번들이면 이전 버전 재실행).
- 사람 검토는 DAG 안에서 기다리지 않는다. 보류 건은 큐에 넣고 DAG는 끝, 승인되면 다음 실행이 반영(25장).
- 규모가 작으면 cron + 스크립트로 시작해도 된다. 대안: Dagster(자산 중심), Prefect.

## 6.3 평가를 운영에 넣기 (24 · 24a장)
| 방법 | 재는 것 | 장점 / 단점 |
|---|---|---|
| CQ 통과율 | 업무 질문에 답하나 | 바로 보임 / 질문 선정에 치우침 |
| 표본 사람 판정 | 들어간 사실의 정확도 | 믿을 만함 / 비용 · 누락은 못 봄 |
| 골든셋(전수 주석) | 빠진 사실(재현율) | 유일하게 누락을 잼 / 만들기 비쌈 |
| LLM 판정 | 대략적 품질 | 싸고 빠름 / 좋게 나오기 쉬움 |
| 실제 과제 성공률 | 쓸모 | 가치가 보임 / 원인 분석 어려움 (발표 4) |

- 우리: CQ 테스트는 매 적재 자동, 층화 표본은 주기적, 골든셋은 프롬프트 · 모델 변경 때. LLM 판정은 표본 고르는 데만.
- 정확도 95/100의 95% 신뢰구간은 대략 89~98%. 숫자 하나보다 구간으로 말한다.
- CQ가 실패하면 원인을 나눈다: 개념이 없으면 온톨로지, 추출 누락이면 프롬프트, ER 오류면 규칙, 수집 누락이면 커넥터.

## 6.4 버전 관리 한 줄 요약 (26장)
- KG = f(원본, 온톨로지, 파이프라인, 모델 · 프롬프트, 승인 기록). 다섯 가지 버전을 고정하면 같은 그래프를 다시 만들 수 있어서, 그래프 DB에 브랜치 기능이 없어도 main / develop을 나눠 비교 · 승격할 수 있다.

2. DAG 안에서 사람 승인을 기다리면 안 되는 이유는?
3. 표본 판정으로는 왜 "빠진 사실"을 못 재나?

<details><summary>답</summary>

1. 두 컬럼을 실제로 조인해 행이 나오는지 확인하고, 나올 때만 저장한다. 2. 파이프라인 전체가 사람 속도에 묶이고 실패 · 재시도가 꼬인다. 보류는 큐로 빼고 다음 실행이 반영한다. 3. 표본은 그래프에 들어간 것 중에서 뽑으므로, 들어가지 않은 사실은 표본에 나올 수 없다.
